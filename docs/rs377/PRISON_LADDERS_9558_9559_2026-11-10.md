# Prison/jail ladders 9558/9559 — verified fix

**Status:** source + isolated gameplay verified; **not deployed** to the live family world.

## Finding

Pinned 377 places `loc 9558` (`prison_ladder_up`, Climb-up) and `loc 9559` (`prison_laddertop`, Climb-down) as three complete same-tile pairs:

| Bottom | Top |
| --- | --- |
| `(2915, 3323, plane 0)` | `(2915, 3323, plane 1)` |
| `(2948, 3213, plane 0)` | `(2948, 3213, plane 1)` |
| `(3010, 3184, plane 0)` | `(3010, 3184, plane 1)` |

There is a fourth placement of 9558 at `(3013, 3179, plane 1)` with no matching top; it is deliberately left unhandled.

`scripts/ladders+stairs/scripts/ladders.rs2` has **no** `oploc1` handler for either loc, so clicking returns the engine default `Nothing interesting happens.` The climb survey in PR #300 classified all six main placements as `NO HANDLER`.

## Fix

`tools/rs377-ladders/apply-prison-ladders.mjs` adds explicit `switch_coord` handlers for the three complete pairs, using the existing `~climb_ladder` procedure and the **loc tile** as the destination (`movecoord(loc_coord, 0, 1, 0)` / `movecoord(loc_coord, 0, -1, 0)`). Using the player tile would land one tile away when approaching from the side.
