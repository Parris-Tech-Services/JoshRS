## 3. Movement: normal click is not an authoritative teleport

- [src/network/game/client/codec/MoveClickDecoder.ts L11–28](https://github.com/LostCityRS/Engine-TS/blob/b5ac859b47915afb545e60e4c1208f25d43cb3fb/src/network/game/client/codec/MoveClickDecoder.ts#L11-L28) decodes starting X and Z with `g2_alt3()`, control flag with `g1()`, then relative waypoints with `g1b()` and `g1b_alt3()` (max 25); minimap clicks consume 14 extra bytes.
- [src/network/game/client/handler/MoveClickHandler.ts L11–56](https://github.com/LostCityRS/Engine-TS/blob/b5ac859b47915afb545e60e4c1208f25d43cb3fb/src/network/game/client/handler/MoveClickHandler.ts#L11-L56) rejects delayed players and invalid control flags or destinations more than 104 tiles from the player; clears ordinary previous pending action, then enqueues waypoints. Depending on `NODE_CLIENT_ROUTEFINDER`, server uses either submitted waypoints or `findPath` through the normal routefinder.
- `MOVE_OPCLICK` is a distinct flow used with a subsequent NPC/loc target packet; lines 26–32 specifically preserve the interaction when the paired operation is split across ticks.
- **Adapter requirement:** encode fields exactly as `MoveClickDecoder` reads them; do not set `player.x`, call `p_teleport` or report success from `socket.write`. Compare subsequent genuine position/tick observations and handle blocked movement.
