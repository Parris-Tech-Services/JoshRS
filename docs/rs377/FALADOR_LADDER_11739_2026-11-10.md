# Falador ladder repair — loc 11739/11740/11741/11742

**Status:** source + isolated gameplay verified; **not deployed** to the live family world.

## Reported symptom

Elrothiro clicked Climb-up on a ladder in Falador and received the engine default `Nothing interesting happens.`

## Actual object

The screenshot area was the Falador Hairdresser's Salon. Pinned 377 map/loc data places:

- `(2946, 3378, plane 0)` — loc **11739**, `Ladder`, `Climb-up`, `forceapproach=north`
- `(2946, 3378, plane 1)` — loc **11741**, `Ladder`, `Climb-down`, `forceapproach=south`
- the same pair at `(2946, 3363)` and `(2954, 3389)`; **11740/11742** are the alternate raised models
- `(2954, 3389)` has two storeys and uses both pair variants

`pack/loc.pack` maps these IDs correctly, but pinned `scripts/ladders+stairs/scripts/ladders.rs2` has **no `oploc1` handler for any of them**. The engine therefore returned its default no-op message.

This is **not** loc 1751 from PR #296. ID 1751 is a different missing handler and has **no map placement** in the pinned 377 maps, so it could not have been the ladder Elrothiro clicked.

## Fix

Add four handlers using the existing `~climb_ladder` procedure and correct same-tile plane transitions:

- 11739/11740: `movecoord(coord(), 0, 1, 0)`, up
- 11741/11742: `movecoord(coord(), 0, -1, 0)`, down

Engine argument order is `movecoord(coord, x, levelDelta, zDelta)`. The earlier experimental call `movecoord(coord(), 0, 0, 1)` moved one tile north instead of changing plane and was discarded.

Installer: `tools/rs377-ladders/apply-falador-vertical.mjs` (guarded, dry-run first, refuses the live runtime, backs up the isolated source, idempotent).
Tests: `tools/rs377-ladders/apply-falador-vertical.test.mjs` (3/3 passing).
CI: `.github/workflows/rs377-directional-ladder.yml` applies the patch to a disposable pinned 377 checkout.
