## 2: What is actually blank? reproducible diagnostic (first engineering milestone)
Before calling a location absent, export a machine-readable audit with these fields:
`source_revision, map_square_id, absolute_region_x, absolute_region_z, plane, source_cache_present, packed_square_present, decoded_tile_count, loc_count, npc_count, walkable_tile_count, navmesh_connected, world_map_overlay_present, expected_2006_land, source_evidence, classification`.

Classifications:
- `BASE_CACHE_MISSING`: region appears on 2006 historical map but missing from user's cache; try authorised same-revision restoration.
- `RENDER_ONLY`: tile/collision present but custom world-map image is blank; fix UI, not terrain.
- `UNIMPLEMENTED_2006`: tile present but NPC/loc/script missing; implement source-compatible behaviour.
- `POST_377_EXPANSION`: appeared in later OSRS/RS3; optional content, not regression.
- `INTENTIONAL_WATER_OR_VOID`: valid non-land tile; do not fill.
- `UNRESOLVED`: insufficient evidence; keep unchanged.

Cross-check against physical map before patching; capture screenshots at known coordinates and inspect host engine cache/pack maps and any client custom `worldmap_377.png`. A blank world-map overlay **does not** prove a missing game region. The source runtime and its pack generation scripts are authoritative for file layout; do not assume cache filenames.

## 3: Expansion engineering contract (Agy)
1. **Snapshot and isolate:** identify actual active paths via `runtime/jparris-377/active.json`; capture consistent save/database backup and current Git revision; never alter a live multiplayer world during a map pack rebuild.
2. **Baseline parity report:** collect map square present/blank metrics and compare to source-era map. Export CSV/JSON diagnostics without copying proprietary cache data into Git.
3. **Separate feature flags:** `JOSHRS_EXPANSION_WORLD=0` default; individual feature flags per region. New world must be off on old saves, leave base-world map packets unchanged until tested.
4. **Coordinate registry:** explicit conflict-free region assignment (no made-up fixed coordinates here). Check against server loaded squares, 377 client coordinate limits, scene base rules, teleports, minimap and network protocol.
5. **One coherent region MVP:** original-authored tile height/collision, ground art, locs, 1 entry point, 1 exit, 3-5 NPC roles, 1 bank or trade service, 2 gathering nodes, 1 short quest/state machine, plus one dungeon or repeatable encounter. Do not claim exact OSRS/RS3 recreation without licensed sources.
6. **World map UI:** derive full overview raster tiles from tested map data (or original art); add click-to-open, zoom and tracking. Do not paste wiki images into game map or redistribute them.
7. **Transport first:** ferries/portals should validate requirements, cost and quest flags, atomically move the player to safe destination tiles and provide safe return. Restrict unfinished land by feature gate.
8. **Content manifests:** store each region's original-written metadata and acceptance tests in this repo; generate runtime-specific configs only after inspecting real engine schema. Never fabricate map/loc/NPC IDs or unverified coordinates.
9. **Regression:** client launch and region load in clean local test world, collision, NPC spawn, animations, item conservation, pathing, quest lock, escape route, save/reload, both players in region, idle/disconnect/teleport and no startup crash.
10. **Promotion:** commit code, run build/test, prove after-restart live login and map interaction; provide explicit VERIFIED or BLOCKED status per region. Never replace Agy's concurrent source edits silently.

## 4: Best first playable vertical slice
**Recommend MAP-OS-03, a compact original-designed archaeological island inspired by Fossil Island's gameplay pattern.** This isolates new map code from major quest hubs and avoids destabilising the existing 377 geography.
- Travel: ferry NPC from a chosen, already-working mainland port; entry via interact, fee and safe teleport.
- Layout: 4–9 coherent map squares **subject to actual map protocol constraints**, with shore, path, dig camp, cliffs, shallow cave and return dock.
- Entities: ferryman, camp guide, collector, trader; dig site, rock, tree, chest; native 377-compatible outfits or original art only.
- Activity: find 3 distinct specimen categories, record collection state, deliver to collector once for reward; include duplicate-protection, full inventory and reconnect.
- Bank/economy: existing bank scripts if confirmed functioning, no item/coin duplications.
- Verify 377 client world map renders it and that game coordinate/movement protocol accepts the chosen square. If not, stop at proof-of-concept, not a fake visual screenshot.
